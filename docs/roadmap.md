# Roadmap ideas

These are product ideas for exploration, not committed features or delivery dates.
Aya should shorten the path from an agent finishing work to a person understanding,
checking and accepting the result.

## First candidates

### Contextual review of answers and artifacts

Select a paragraph, table row, widget element, image region or diff line and leave
feedback. Batch several comments into one follow-up. Include the exact selection,
artifact revision and surrounding context so the agent can make a precise change.

### Verifiable task results

Finish a task with a compact result card: what changed, a preview, the diff, checks
performed and decisions still needed. Distinguish completed work from verified
work. Link check results to the actual run and code revision rather than treating
an agent's statement as proof.

## Further exploration

### An attention inbox across sessions

Collect questions, approvals, errors and work ready for review in one calm queue.
Give each item enough context and a direct action. Make it clear which agent needs
a person now, without requiring every terminal to be watched or every step to
produce a notification.

### Explicit handoffs between harnesses

Ask another harness to review or continue a task with a selected context package:
goal, current diff, chosen messages, artifacts and check results. Preview what will
be shared. Keep source conversations separate and preserve who proposed, checked
or changed each result. Return reviews to the originating task.

### Artifacts as a persistent project workspace

Pin artifacts across sessions, compare revisions side by side, keep comments tied
to a version and preserve widget settings when content updates. Explore living
mockups, reports and dashboards maintained across tasks. Distinguish local widget
interactions and suggestions from actions that require harness permissions.

## Everyday usability candidates

- Edit and resend a message.
- Branch a conversation from a selected point, where supported by the harness.
- Search conversations across sessions with explicit project/account boundaries.
- Inspect the context being sent and the capabilities available from each harness.

## Suggested exploration order

Prototype contextual artifact review first, then verifiable task-result cards.
Evaluate a complete workflow: create a mockup, leave several targeted comments,
receive a revised artifact, compare versions and accept the result. Measure the
steps and context copying needed to complete that workflow before expanding scope.
